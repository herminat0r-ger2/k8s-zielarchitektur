KRITIS Zielarchitektur — 2 Standorte + gestreckter Cluster

Standort A und B je mit eigenem Proxmox-Cluster auf lokalem Alletra-Storage (kein Sync zwischen den Systemen) · zusätzlich EIN gestreckter Proxmox-Cluster über beide Standorte (VMs + Kubernetes) auf dem Alletra-Metro-Storage · 3 Kubernetes-Cluster · IaC via OpenTofu, Patch-Management via Uyuni

Topologie

  • • 2 eigenständige Proxmox-Cluster (A, B) auf lokalem Alletra-Storage — kein Storage-Sync
  • • Zusätzlich 1 gestreckter Proxmox-Cluster über beide Standorte (VMs + Kubernetes)
  • • 3 Kubernetes-Cluster: K8s-A, K8s-B, K8s-Stretch
  • • DB-Replikation zwischen A und B: CloudNativePG auf Anwendungsebene

Storage

  • • HPE Alletra MP B10000, 2 Systeme — LUNs lokal-only und Metro auf denselben Arrays
  • • Block: iSCSI / FC / NVMe-oF (FC oder TCP), Dual-Fabric + Multipath
  • • K8s-PVs via HPE CSI Driver (Active Peer Persistence)
  • • Metro-Paar: Peer Persistence, synchron gespiegelt, RPO 0

Betrieb & Notfall

  • • IaC: OpenTofu (Provider bpg/proxmox) · Patch-Management: Uyuni (Salt)
  • • Backup: PBS (VMs), Velero → MinIO (K8s), CloudNativePG-Backup (DBs)
  • • Übernahme per Replikation — Restore nur als Sicherheitsnetz
  • • etcd: 3 Mitglieder, alle an einem Standort; Ablage in Test
